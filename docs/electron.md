# Raising Electron's version

Fixes for Chromium bugs exploited in the wild ship within days ([fork.md](spec/fork.md#electron-and-chromium)). When VS Code has not shipped the fixed Electron, Planish raises the Electron that its pinned VS Code tag builds with, as VSCodium has done. These are the steps, for a person or a coding agent.

1. **Check that it is needed.** [Chrome's release notes](https://chromereleases.googleblog.com/) say when "an exploit … exists in the wild". Find the Electron release that carries the fix in the major version VS Code ships: VS Code's `.npmrc`, at the tag in `upstream/stable.json`, pins it as `target`, and [Electron's releases](https://releases.electronjs.org/) give each release's Chromium version and fixes. If a newer VS Code that VSCodium has adopted already ships it, take that instead ([Keeping up with upstream](spec/fork.md#keeping-up-with-upstream)).
2. **Write the patch.** On a branch from `main`, run `python3 -I -B dev/update_electron.py VERSION`. It fetches VS Code's `.npmrc`, `build/checksums/electron.txt` and `cgmanifest.json` at that tag, with Electron's `SHASUMS256.txt` and the commit of its tag, and writes `patches/user/00-build-update-electron.patch`. It refuses a version outside VS Code's Electron major version, whose Chromium and Node.js versions differ, and a release missing any file VS Code checks.
3. **Check it.** Fetch VSCodium's master (`git fetch --no-tags https://github.com/VSCodium/vscodium.git master:refs/vscodium/master`), then run `python3 -I -B dev/check_fences.py refs/vscodium/master` and `python3 -I -B -m unittest discover --start-directory dev --pattern 'test_*.py'`. The fence report lists the patch's checksum and manifest lines as unfenced (Electron update); only this patch may leave them so.
4. **Build it.** Open a pull request. CI builds all three platforms, which downloads the new Electron and checks it against the checksums, and runs the smoke tests. The release build also refuses an app whose Electron differs from the pin.
5. **Release it.** Once merged, tag a release. Its notes give the Electron and Chromium versions; add a line starting `Security fix:`, naming the Chromium bug, before publishing, so that installed apps are offered it without the 120-hour wait ([fork.md](spec/fork.md#build-release-and-updates)).
6. **Remove it.** When a VS Code release that ships this Electron or a newer one is taken, delete the patch in the same pull request: it no longer applies once VS Code's pin moves.
